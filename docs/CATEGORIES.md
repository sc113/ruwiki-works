# Категории обслуживания

Два независимых действия работают через общую очередь:

- **Создание категорий:** ежедневно в 05:00 МСК. Выбираются непустые месячные категории, у которых отсутствует страница и найден точный формат названия.
- **Проверка оформления:** по понедельникам в 05:00 МСК, только для ещё не проверенных существующих категорий из набора форматов. Оформление автоматически приводится к ожидаемому вики-тексту. В последний день месяца в 05:00 выполняется полный проход по всем существующим категориям этого набора. При совпадении двух сроков запускается один полный проход.

Поиск обновляет рабочий набор каждые 6 часов. Расписания, источники, типы форматов, начальная дата проверки, лимит категорий и автосохранение доступны в параметрах admin. «С нуля» принудительно проверяет все существующие категории из набора, сохраняя историю запусков. Выключенное автосохранение позволяет просмотреть подготовленные изменения без правок и без новых отметок проверки.

## Форматы

Перед каждым проходом читается актуальная ревизия [вики-таблицы форматов](https://ru.wikipedia.org/wiki/Проект:Технические_работы/Список_сообщений_для_статей/Категории_для_создания):

- `GenerateTemplates: надстрочные` задаёт полный вики-текст сложных категорий.
- `GenerateTemplates2: надстрочные` и `GenerateTemplates2: боксы` задают параметры `Категория к ежемесячной очистке`.

Поддерживаются `<text_month_year>`, `<month_name>`, `<year>` и `<yyyy-mm>`. Таблица разбирается с учётом `nowiki`, вложенных шаблонов и разделителей ячеек. Неполные таблицы, неизвестные переменные и противоречащие определения останавливают проход. Сохранённые форматы при этом не заменяются и не используются для новых правок.

Отметка проверки сохраняется по названию категории; ревизия и отпечаток ожидаемого текста служат диагностикой. Еженедельный проход пропускает уже проверенные категории, даже если изменились страница или её формат. При полной проверке учитывается актуальная таблица и заново проверяются все существующие категории из набора. Неудачные сохранения и проверки без записи не помечают категорию обработанной.

## Получение категорий

На Toolforge выполняются read-only запросы к Wiki Replicas `ruwiki_p`. Сочетание таблиц `category` и `page` даёт непустые категории без страницы в настроенном префиксе. Для оформления выбираются существующие страницы категорий без перенаправлений. В рабочем наборе сохраняются только точные названия из таблицы форматов; для оформления дополнительно применяется настроенный диапазон месяцев. Авторизация использует стандартный приватный `~/replica.my.cnf`; содержимое файла не публикуется. Ручной запуск Quarry не требуется.

Категории без известного формата не сохраняются в рабочем наборе, не показываются в отчёте и не обрабатываются. Общий список всех несозданных категорий не собирается.

При локальной работе без файла доступа к репликам используется MediaWiki API `allcategories` и `allpages`. Полученные страницы фильтруются по тому же набору форматов. Недоступность настроенной базы реплик отображается как ошибка обновления, без обхода всей Википедии.

Снимок рабочего набора сохраняется один раз в сжатом виде. Тексты форматов и списки ожидающих категорий не дублируются в архивах запусков.

## Запись и журналы

Перед созданием повторно читаются актуальные содержимое и заполненность категории через API. Сохранение использует `createonly`, поэтому не перезаписывает страницу, созданную другим участником. Исправление существующей категории использует `nocreate` и проверку исходной ревизии. Перенаправления не разворачиваются.

Правки имеют флаг бота и не помечаются малыми. Используются общие ограничения частоты, пауза при ошибках API, запреты бота, проверка редактируемых участником страниц и команды паузы/остановки. Публичный журнал содержит результат обработки страницы; admin видит описание правки, исходный и ожидаемый текст, используемую конфигурацию и ревизию таблицы.
