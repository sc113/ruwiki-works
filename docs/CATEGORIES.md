# Категории обслуживания

Два независимых действия работают через общую очередь:

- **Создание категорий:** ежедневно в 04:00 МСК. Выбираются непустые месячные категории, у которых отсутствует страница и найден точный формат названия.
- **Проверка оформления:** по понедельникам в 05:00 МСК. Оформление автоматически приводится к ожидаемому вики-тексту. В последний день месяца в 05:00 выполняется полный проход. При совпадении двух сроков запускается один полный проход.

Поиск обновляет списки каждые 6 часов. Расписания, источники, типы форматов, начальная дата проверки, лимит категорий и автосохранение доступны в параметрах admin. «С нуля» принудительно проверяет все категории, сохраняя историю запусков. Выключенное автосохранение позволяет просмотреть подготовленные изменения без правок и без новых отметок проверки.

## Форматы

Перед каждым проходом читается актуальная ревизия [вики-таблицы форматов](https://ru.wikipedia.org/wiki/Проект:Технические_работы/Список_сообщений_для_статей/Категории_для_создания):

- `GenerateTemplates: надстрочные` задаёт полный вики-текст сложных категорий.
- `GenerateTemplates2: надстрочные` и `GenerateTemplates2: боксы` задают параметры `Категория к ежемесячной очистке`.

Поддерживаются `<text_month_year>`, `<month_name>`, `<year>` и `<yyyy-mm>`. Таблица разбирается с учётом `nowiki`, вложенных шаблонов и разделителей ячеек. Неполные таблицы, неизвестные переменные и противоречащие определения останавливают проход. Сохранённые форматы при этом не заменяются и не используются для новых правок.

Отметка проверки содержит ревизию категории и отпечаток ожидаемого текста. Изменение категории или её формата возвращает страницу в очередь проверки. Изменение другого формата не отменяет отметку. Неудачные сохранения и проверки без записи не помечают категорию обработанной.

## Получение категорий

На Toolforge выполняются read-only запросы к Wiki Replicas `ruwiki_p`. Сочетание таблиц `category` и `page` даёт непустые категории без страницы, включая категории вне обслуживания. Авторизация использует стандартный приватный `~/replica.my.cnf`; содержимое файла не публикуется. Ручной запуск Quarry не требуется.

Полный список виден во вкладке «Без страницы» с поиском и разбивкой на страницы. Категории без известного формата автоматически не создаются. Неизвестные месячные категории обслуживания отображаются как требующие ручного исправления.

При локальной работе без файла доступа к репликам используется MediaWiki API `allcategories` и `allpages`. Такой список ограничен настроенным префиксом: полный обход всей Википедии через API не выполняется. Недоступность настроенной базы реплик отображается как ошибка обновления, без затратного обхода всей Википедии.

Полный снимок непустых отсутствующих категорий сохраняется один раз в сжатом виде. Он не копируется в журналы каждого запуска. Тексты форматов и полный список ожидающих категорий также не дублируются в архивах запусков.

## Запись и журналы

Перед созданием повторно читаются актуальные содержимое и заполненность категории через API. Сохранение использует `createonly`, поэтому не перезаписывает страницу, созданную другим участником. Исправление существующей категории использует `nocreate` и проверку исходной ревизии. Перенаправления не разворачиваются.

Правки имеют флаг бота и не помечаются малыми. Используются общие ограничения частоты, пауза при ошибках API, запреты бота, проверка редактируемых участником страниц и команды паузы/остановки. Публичный журнал содержит результат обработки страницы; admin видит описание правки, исходный и ожидаемый текст, используемую конфигурацию и ревизию таблицы.
