# Шаблоны о проблемах

Раздел `/processors/maintenance` содержит три независимых действия:

| Действие | Результат |
| --- | --- |
| `maintenance-dates` | Заполняет даты в обычных шаблонах о проблемах |
| `maintenance-rq` | Заменяет распознанные позиционные параметры RQ вложенными шаблонами о проблемах |
| `maintenance-rq-unwrap` | Снимает обёртку RQ, если внутри ровно один шаблон о проблеме |

У каждого действия собственные настройки, очередь, отчёт и история. Замена параметров сохраняет обёртку RQ; её снятие выполняет только третье действие.

## Источники и расписание

Монитор каждые **6 часов** обновляет категории и публичные счётчики. Обработка назначается ежедневно на **03:00 МСК**. Расписание каждого действия редактируется рядом с кнопками управления и применяется без перезапуска процессов. Все действия используют общий последовательный исполнитель.

Для дат проверяются прямые подкатегории, один уровень, категории «Отслеживающие категории:Статьи с шаблонами-сообщениями без указанных дат». Для параметров RQ — категория «Википедия:Статьи к замене параметров шаблона rq», для одиночного RQ — «Википедия:Статьи с одной проблемой в шаблоне rq». Отбираются статьи пространства 0; совпадения между подкатегориями объединяются.

«К обработке» показывает текущий список статей. «Исправить» — остаток после завершённого прохода с сохранением правок. Непустые категории дают статус ошибки и публичный список для ручного исправления. Новые статьи между проходами не становятся ручными проблемами заранее. Когда статья выходит из категории, монитор убирает её из актуальных остатков.

Ошибка не вызывает немедленный новый проход: обычная повторная обработка выполняется следующей ночью. Ручной запуск доступен admin. Проверка без записи показывает предлагаемые изменения и не оценивает очистку категорий.

## Правила обработки

Дата определяется по ревизии установки шаблона. Учитываются перенаправления, повторные установки и шаблоны разделов. Скрытая или неполная история и неоднозначное сопоставление раздела дают ошибку вместо предполагаемой даты.

Заполненная `дата` или `date` сохраняется, пустая заполняется. Позиционный параметр `1` с датой в формате `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД` удаляется после нахождения даты по истории. Другие параметры, вложенная разметка и комментарии сохраняются. Примеры в комментариях, nowiki и заголовках не изменяются.

RQ заменяет только распознанные позиционные параметры. Совпадающие назначения объединяются; существующие вложенные шаблоны и их даты сохраняются. Неизвестные и именованные параметры, `topic` и комментарии остаются. Параметр `all` по умолчанию исключает статью из обработки. На сам контейнер RQ дата не ставится.

Разворачивание допускается, если первый позиционный параметр содержит ровно один шаблон проблемы и нет дополнительных заполненных позиционных или именованных параметров. Дата и параметры вложенного шаблона сохраняются. Вспомогательные шаблоны внутри его параметров не считаются второй проблемой. Неоднозначные записи остаются без изменений; вложенные обёртки обрабатываются изнутри наружу.

## Параметры admin

| Параметры | Назначение |
| --- | --- |
| Категории | Источники статей для выбранного действия |
| Поиск даты | Последняя непрерывная установка, первое появление или двоичный поиск с проверкой ранних версий |
| Лимит ревизий | Ограничение чтения истории; 0 означает отсутствие лимита |
| Шаблоны разделов | Категория-источник, автоматическое обновление и редактируемый построчный список |
| Соответствия RQ | Строки `параметр=шаблон`, список параметров пропуска и начальный префикс сортировки |
| Автосохранение | Разрешение сохранять правки в рамках действия |
| Диагностика | Подробные события в полном журнале |
| Расписание | Интервал поиска и время ежедневного запуска |

Для разворачивания RQ доступны категория, автосохранение, диагностика и расписание; чтение истории дат ему не требуется. Список шаблонов разделов автоматически обновляется не чаще раза в сутки. Ручное редактирование списка отключает автоматическое обновление до его повторного включения. `TOOLFORGE_WIKI_WRITE=false` запрещает запись независимо от настроек действия.

## Результаты и журналы

Страница действия следует общему порядку: обзор и управление → параметры → результаты и отчёты. Вкладки «К обработке», «Проблемы» и «Лог» показывают ожидающие статьи, остатки и историю запусков.

Публичные HTML/TXT/JSON журналы показывают одну строку на обработанную статью с результатом: сохранено, проверено без записи, пропущено или ошибка. Для сохранённых изменений указаны шаблоны и даты. Полная диагностика, настройки, причины пропусков и различия текста доступны admin. Отчёты ОБКАТ публичны.

## Запуск и проверка

```bash
python -m toolforge_app refresh-maintenance
python -m toolforge_app worker --task all
python -m toolforge_app worker --task monitor
python -m pytest -q
```

`refresh-maintenance` только читает категории. Исполнитель и монитор запускаются отдельными процессами. Тесты используют имитацию API и сохранения, без реальных правок Википедии.
