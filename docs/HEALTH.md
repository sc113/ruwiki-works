# Состояние, уведомления и повторные проверки

Общий индикатор над содержимым показывает работу, выполнение текущей задачи, паузу или остановку. Отсутствие свежего сигнала исполнителя показывается здесь один раз. У отдельных действий остаются их собственные результаты, ошибки и место в очереди.

В режиме admin раскрываются последние сигналы двух процессов и ссылка на `/notifications`. Здесь сохраняются сбои исполнителя/монитора, ошибки запусков, устаревшие данные и пропущенные ночные сроки. Один продолжающийся сбой создаёт одно уведомление. «Прочитано» сохраняется; после восстановления появляется отметка «Устранено». Новый сбой после восстановления — новое уведомление. Внешние сообщения сайт не отправляет.

Проверка просроченного ежедневного запуска учитывает очередь: пока другое действие работает, ожидание не считается пропуском. Задачи на паузе или остановленные не получают уведомление о пропущенном сроке. Перенос расписания устанавливает новую точку отсчёта.

## Поиск и обработка

| Раздел | Поиск | Обработка, МСК |
|---|---|---|
| ОБКАТ | Каждые 5 минут | Через 15 минут после последней правки |
| Шаблоны о проблемах | Каждые 6 часов | Ежедневно, 03:00 |
| Плохие и грубые переводы | Каждые 6 часов | Ежедневно, 04:00 |
| Шаблоны разделов | Каждые 6 часов | Ежедневно, 04:00 |

Форматирование ОБКАТ — последний день месяца, 23:30 МСК. admin меняет частоту поиска, ежедневное время и таймеры ОБКАТ в общей форме расписания. Поиск выполняется от предыдущей проверки, независимо от ночного запуска. Первое наблюдение и явное обновление счётчиков выполняются сразу. Запуски в один срок выполняются последовательно в порядке главной страницы.

Монитор разделов при очередном поиске получает свежие включения шаблонов; долгий кеш не задерживает поиск новых статей. Кеш перенаправлений остаётся отдельным параметром. Данные считаются устаревшими после ожидаемого интервала с запасом: 5 минут для ОБКАТ и час для остальных списков.

## Пропущенные статьи и история проблем

admin видит «Вернуть в очередь» рядом с каждой пропущенной статьёй переводов/разделов. Повторные нажатия объединяются. Обработка заново проверяет только выбранную статью и её текущий источник. Отметки остальных статей и история запусков сохраняются. При технической ошибке выбранная статья остаётся назначенной на следующий ночной срок. Пауза сохраняет очередь; остановка отменяет её. Предпросмотр admin блокирует любые команды.

В ручных проблемах одной строкой показаны первое обнаружение и последнее подтверждение. Эти даты берутся из фактических наблюдений, а не времени просмотра страницы. Начало истории соответствует самому раннему доступному наблюдению, а не предполагаемому времени появления проблемы в Википедии. Повторное появление после устранения сохраняет первое обнаружение и увеличивает число появлений.

## Контроль фоновых процессов

Сигнал обновляется во время запросов к API и между проходами. Через 5 минут без сигнала процесс считается недоступным.

```sh
python -m toolforge_app check-health executor
python -m toolforge_app check-health monitor
```

Команды только читают состояние и возвращают код 0/1. HTTP-проверки `/healthz/workers/executor` и `/healthz/workers/monitor` возвращают 200/503; `/healthz` отдельно проверяет сайт и базу.

В `deploy/jobs.yaml.example` добавлены проверки через `deploy/health-check.sh`. Toolforge умеет перезапускать непрерывное задание при отказе его проверки; параметры и поведение описаны в [официальной документации Jobs](https://wikitech.wikimedia.org/wiki/Help:Toolforge/Running_jobs#Configuring_health_checks_for_jobs). Настройка `emails: onfailure` сохранена. Реальные проверки Toolforge начнут действовать после загрузки файла заданий в созданный инструмент.
