# Плохие и грубые переводы

Раздел `/processors/translations` содержит два независимых действия:

| Действие | Источник языка и оригинала |
| --- | --- |
| `translations-categories` | Комментарий к созданию статьи |
| `translations-talk` | Шаблон перевода на странице обсуждения |

Оба выбирают статьи из категорий плохих и грубых переводов с неуказанным языком. Монитор обновляет списки каждые **6 часов**; обработка назначается на **04:00 МСК**. Действия выполняются последовательно и сохраняют независимые настройки, отметки и историю.

## Получение данных

Первое действие читает комментарий к первой ревизии статьи и ищет ссылку на оригинал. Второе читает настроенный шаблон на странице обсуждения; по умолчанию это «Переведённая статья».

Поддерживаются интервики, адреса `/wiki/…` и `index.php?title=…`. Название оригинала извлекается из цели ссылки. Список допустимых языковых разделов получается через `siteinfo/interwikimap` и кешируется на сутки.

Изменяются только настроенные шаблоны «Плохой перевод», «Грубый перевод» и их перенаправления. Добавляются `язык` и `оригинал`, заполняются пустые значения. Заполненные отличающиеся значения не перезаписываются; конфликты и несколько разных источников требуют ручной проверки. Первый позиционный параметр, отмечающий раздел, сохраняется. Значение второго позиционного параметра переносится в `оригинал`, если оно не конфликтует с найденным источником. При изменении данных перевода `date` переименовывается в `дата`.

## Учёт проверенных статей

Результат законченной проверки хранится в `article_checks` отдельно для каждого действия. Обычные проходы выбирают только новые названия. Перезапуск процесса и пауза сохраняют прогресс. Последующие правки уже проверенной статьи автоматически не снимают отметку.

Отсутствие источника, страницы обсуждения, подходящего шаблона или полных данных считается пропуском. Такие записи видны во вкладке «Пропущено» и не увеличивают счётчик ручных проблем. Конфликты показываются отдельно. Технический сбой не создаёт отметку законченной проверки и допускает повтор в следующий проход. Выход статьи из отслеживаемых категорий убирает её из актуального отчёта, сохраняя историю запусков.

Кнопка admin **«С нуля»** назначает повторную проверку всех статей выбранного действия. При начале исполнения сбрасываются только его отметки; история и другое действие сохраняются. Продолжение после паузы не повторяет сброс. В режиме без записи проверка обходит отметки, сохраняя их; предлагаемые изменения не считаются сохранёнными.

## Настройки и журналы

Admin редактирует категории, шаблоны перевода, шаблон на СО, автосохранение, подробную диагностику, частоту поиска и время ежедневного запуска. Настройки, очередь, отметки и журналы хранятся в общей базе. Для записи также требуется глобальное разрешение `TOOLFORGE_WIKI_WRITE`.

Публичные HTML/TXT/JSON журналы показывают обработанные статьи и краткий результат каждой проверки. Для сохранённых изменений указаны шаблоны, язык и оригинал. Admin получает конфигурацию запуска, источник и ревизию, причины пропусков, ошибки и различия текста. Общая история содержит длительность и изменения состава отчёта.

Описание правки перечисляет каждый изменённый шаблон и значения `язык` и `оригинал`. Источник — ссылка на дифф первой правки либо шаблон «Переведённая статья» на СО со ссылками на страницу обсуждения и её проверенную ревизию. Полный комментарий доступен admin и при проверке без сохранения. В пределах ограничения MediaWiki длинное описание сокращается без разрыва ссылок; ссылка на ревизию источника сохраняется.

## Запуск

```bash
python -m toolforge_app refresh-translations
python -m toolforge_app worker --task all
python -m toolforge_app worker --task monitor
```

`refresh-translations` обновляет списки без правок. Исполнитель и монитор работают отдельными процессами. Сохранение учитывает базовую ревизию и общие ограничения API: [API_SAFETY.md](API_SAFETY.md).
